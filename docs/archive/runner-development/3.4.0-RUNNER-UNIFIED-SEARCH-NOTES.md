# RunMind 3.4.0 — Runner unified search update

- Consolidated launcher providers into one result list; removed the permanently split results/inline-answer pane.
- Added RunMind global query mode and configurable action keyword (default `llm`).
- Global mode contributes RunMind results for each non-empty search while retaining application, file, URL and Calculator results.
- Keyword mode invokes RunMind only for the configured keyword and prompt.
- Search input explicitly uses active theme foreground, caret, selection and selected-text colors.
- Preserved debounced inline generation and cancellation when a newer query arrives.
- Runner settings remain independent of PowerToys Run and Command Palette settings.

Validation: 274 Node regression tests passed. XAML, App.xaml and project XML parsed successfully. A Windows/.NET 10 Release build was not available in this environment and must be run on Windows.

## Runner window/settings UX correction

- Main Runner window is movable/resizable using WPF WindowChrome.

## Follow-up: theme selector labels and launcher search field

The user reported two remaining visual defects in the Runner settings/launcher UI. This source corrects both:

- **Theme selector labels:** Light and Dark theme ComboBoxes now use an explicit `ThemeNameTemplate` DataTemplate bound to `ThemeDefinition.Name`. This avoids the custom ComboBox selected-item presenter falling back to the record-generated `ToString()` value (for example, `ThemeDefinition { Id = ..., Name = ... }`). The template explicitly uses the active `RunnerText` brush and truncates long names cleanly.
- **Launcher search input:** the primary inline search TextBox is now 52 DIPs high with zero extra vertical padding, centered content, and explicit ClearType text rendering. The surrounding 68-DIP search surface remains unchanged.

## Open Chat handoff correction

Runner does not host an embedded/duplicate chat window. Open Chat hands off to RunMind Standalone, the actual Full Agent host. Inline prompt and answer text are carried as transcript context only and are not automatically resubmitted. An existing Standalone process receives the handoff through a current-user-only named pipe and opens a new Full Agent conversation window in that process; otherwise Runner starts the located Standalone executable with a bounded handoff file. The Runner project has no WebView2 dependency or bundled ChatWindow runtime.
