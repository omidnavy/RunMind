# Build and setup

This guide describes the current RunMind 3.5.0 source tree. It is a **full source-project snapshot**, not a changed-files overlay.

## Supported environment

- Windows 11 x64, build 22621 or later. ARM64 is not currently packaged.
- .NET 10 SDK and Windows x64 targeting/runtime packs.
- .NET 10 Desktop Runtime for the framework-dependent Standalone and Runner publications.
- Microsoft Edge WebView2 Runtime. The hosts check for it during startup and coordinate Evergreen runtime installation for the current Windows user when required.
- Node.js 24 or later for the automated JavaScript regression suite and Node-based developer integrations.
- Git for Windows on `PATH` for Git-backed project tools.
- Microsoft PowerToys only for the PowerToys Run plugin and Command Palette extension.

The source ZIP includes the solution, shared code/resources, reference assemblies under `lib\x64`, assets, screenshots, tests and scripts. PDF/OCR runtime files under `Vendor` and `OCR\tessdata` are generated by the first release build.

## Build all hosts and release artifacts

Run from the repository root in Windows Command Prompt or PowerShell:

```bat
Build-Release-x64.bat
```

The script performs nine steps: prepare PDF/OCR assets; clean; restore the solution for `win-x64`; build all four host projects; package/sign the Command Palette MSIX; publish Standalone; publish Runner; verify the host executables; and create four GitHub release ZIPs.

The four host projects are:

1. **RunMind Standalone** — full workspace.
2. **PowerToys Run plugin** — full Agent host inside PowerToys Run.
3. **PowerToys Command Palette extension** — full Agent host packaged as MSIX.
4. **RunMind Runner** — optional restricted Quick Host; not a Full Agent.

The release script **does not install** any host. It also removes retired Runner/Command Palette source files left by an older overlay extraction before building.

### Output locations

| Artifact | Output |
|---|---|
| PowerToys Run plugin DLL/resources | `Community.PowerToys.Run.Plugin.RunMind\bin\x64\Release\` |
| Standalone publish | `Release\Standalone\win-x64\publish\` |
| Runner publish | `Release\Runner\win-x64\publish\` |
| Command Palette MSIX and public certificate | `Release\CommandPalette\x64\` |
| Four GitHub release ZIPs | `Release\GitHub-Releases\` |

The published Standalone executable is `Release\Standalone\win-x64\publish\RunMind.exe`. Runner is `Release\Runner\win-x64\publish\RunMind.Runner.exe`.

The builder creates `standalone-[version].zip`, `runner-[version].zip`, `powertoysrun-[version].zip`, and `commandpalette-[version].zip` in `Release\GitHub-Releases`. The PowerToys Run archive contains its installer BAT and plugin output; the Command Palette archive contains its installer BAT, deployment scripts, signed MSIX and public certificate; the Runner archive contains its install/uninstall scripts. Each archive is self-contained for its corresponding host installation workflow.

## Install or update a host

Install only after the release build succeeds.

### PowerToys Run

1. Exit PowerToys completely from its system-tray menu.
2. Run `Install-RunMind-PowerToys-Run.bat`.
3. Start PowerToys again and open PowerToys Run.

The installer refuses to copy while PowerToys is running. It mirrors the already-built plugin output into the current user's PowerToys Run plugin directory and removes stale deployed files. It does not build the solution.

### Command Palette

Run `Install-RunMind-CommandPalette.bat` to install the already-built, signed MSIX. The installer verifies package trust/identity and may request administrator approval when adding the signing certificate to the machine trust store. It does not build or package the extension. After installation, reload Command Palette extensions from PowerToys.

Use `Install-RunMind-CommandPalette.bat uninstall` to remove the current user's package.

### RunMind Runner

Run `Install-RunMind-Runner.ps1` to install the already-published Runner for the current user. Add `-DesktopShortcut` to create an optional Desktop shortcut. Runner is independent of PowerToys and does not start with Windows unless the user enables that setting in Runner.

To remove it, close Runner and run the installed `Uninstall-RunMind-Runner.ps1`. By default, the uninstaller removes Runner settings in `%LOCALAPPDATA%\RunMind\Runner`; pass `-KeepSettings` to retain them. Standalone, PowerToys Run and Command Palette are not modified.

## Prepare PDF and OCR runtime assets

`Build-Release-x64.bat` invokes `Prepare-RunMind-OCR.ps1` before compilation. The script uses these npm package versions:

- PDF.js `6.5.438`
- Tesseract.js `7.0.0`
- Tesseract core `7.0.0`

It also downloads English (`eng`) and Persian (`fas`) trained data from the upstream `tessdata_fast` GitHub `main` branch. The npm package URLs include fixed versions, but the downloaded `.tgz` archives are **not checked against a committed SHA-512 integrity value**. The language-data URL follows the mutable `main` branch and the downloaded files are not checked against committed hashes. The preparation step is therefore not fully reproducible byte-for-byte or integrity-verified. Pin both package tarball integrity values and language-data commits/checksums before treating this pipeline as supply-chain reproducible.

The first preparation requires internet access and Windows `tar.exe`. The generated resources are ignored by Git and are not expected to be present in a clean source checkout. Subsequent builds can run offline only while all generated runtime files remain available and pass the script's asset checks.

## Connect a model provider

RunMind supports Ollama, LM Studio and configured OpenAI-compatible endpoints.

- Ollama commonly listens at `http://localhost:11434`.
- LM Studio commonly exposes an OpenAI-compatible API at `http://localhost:1234/v1`.
- Allow the WebView origin `https://localhost` in the model server's CORS settings. For Ollama, configure `OLLAMA_ORIGINS`; for LM Studio, enable CORS in its local server settings.

Model features such as vision and tool calling depend on the selected model/provider. Remote endpoints and MCP servers may receive prompts or data; connect only services you trust.

## Validate the source on Windows

After installing Node.js 24+ and the .NET 10 SDK, run:

```powershell
.\Validate-RunMind-Windows.ps1
```

The validation script runs the portable Node test suite, invokes the complete x64 release build, then verifies all four host outputs plus the Command Palette MSIX/certificate. It does not install anything. Use `-SkipBuild` when you want only the Node regression suite and existing build-output checks.

Portable tests do not replace manual WebView2, PowerToys, MSIX, process-management, GPU-counter or installer acceptance. See the relevant checklists linked from the [README](../../README.md).

## Version metadata

The current source version is **3.5.0**. All four host projects declare `3.5.0`; the PowerToys Run plugin manifest, MCP client identification and Runner uninstall display metadata also use `3.5.0`. Command Palette uses the required four-part MSIX project/package identity `3.5.0.0`. A portable regression test checks these declarations together. Generated assembly/package metadata and install/update behavior still require validation on Windows.

## Repository hygiene

- Do not commit `bin`, `obj`, `Release`, generated `Vendor`/OCR resources, personal settings, credentials, or test/runtime logs.
- Keep the product overview in the repository [README](../../README.md), capability semantics in the [Feature Matrix](../product/FEATURE-MATRIX.md), project verification in [Build Status](../project/BUILD-STATUS.md), and historical material in the [archive](../archive/README.md).
- Historical archived reports are snapshots and do not certify the current tree.
