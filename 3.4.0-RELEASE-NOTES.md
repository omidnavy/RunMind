# RunMind 3.4.0 — Complete Optional Runner

## Summary

RunMind 3.4.0 adds the complete optional standalone Runner host. Runner is a native Windows launcher with a plugin-based result registry, an inline RunMind LLM experience and independent provider/settings storage. Full chat is handed off to the actual RunMind Standalone application; Runner does not host a duplicate chat UI or require PowerToys.

## Launcher plugins

- Applications — bounded Start Menu shortcut discovery and explicit launch.
- Files & Folders — explicit rooted file and folder opening.
- URLs — HTTP/HTTPS opening only.
- Calculator — safe local arithmetic parser with copyable result.
- RunMind — real inline model answers using the same `llm <prompt>` activation style as PowerToys Run.

The launcher has an internal first-party plugin contract. Future RunMind launcher features can register without modifying the shell. Arbitrary third-party plugin code loading is not included.

## RunMind inline model

Runner has an independent Quick/inline provider profile for Ollama's native API and LM Studio's native/OpenAI-compatible APIs. It supports model discovery, model override syntax (`llm > model > prompt`), per-provider keys and custom auth headers, reasoning options, request/discovery timeouts, Ollama keep-alive and CPU thread options, optional generation parameters, and the Nemotron 3.5 Bolt E4B compatibility flag.

The full RunMind chat provider configuration remains separate. Runner inline credentials use Windows DPAPI CurrentUser protection and are not written to the JSON settings file.

## Chat, appearance and host boundary

- Open Chat hands off to the actual RunMind Standalone application.
- Completed or partial inline answers are transferred into the real Standalone transcript as context, without automatically generating them a second time.
- Runner shares the RunMind theme catalogue for its native launcher UI; the full chat uses Standalone's normal UI, settings and theme infrastructure.
- Runner itself has no workspace, MCP, Skills, developer tools or Full Agent bridge. Those capabilities remain in Standalone.

## Performance and lifecycle

The native launcher and hotkey are initialized without WebView2 startup or provider network requests. Application indexing runs asynchronously. Model discovery/generation starts only for explicit `llm <prompt>` searches (unless global mode is enabled), is debounced and cancellable, and has configured time/response limits. Open Chat launches or hands off to the real Standalone application; WebView2 is only part of that Standalone host.

Runner includes a configurable global hotkey, tray, single-instance behavior, optional current-user sign-in startup, and independent current-user install/uninstall scripts.

## Compatibility and validation

- Target framework: .NET 10 Windows x64.
- Provider integrations: Ollama native API and LM Studio native/OpenAI-compatible APIs.
- Full solution build and Windows runtime/installer acceptance remain target-machine gates because this packaging environment has no .NET SDK or Windows runtime.
- Portable test, JavaScript syntax and XML/source validation results are recorded in `BUILD-STATUS.md`.

## Not included in 3.4.0

Quick Agentic Mode and system-management tool execution are intentionally not part of this Runner release. They are the next milestone and will be added through one shared restricted Quick Agent Core to Runner, PowerToys Run and Command Palette. Full Agent remains Standalone-only.

## Runner empty state and real Standalone handoff

- Removed all illustrative quick-start examples and suggestion cards. An empty Runner shows only its compact launcher shell; the result panel remains hidden until a plugin actually returns a result.
- Removed `RunnerChatWindow` and its WebView2 package/assets from the Runner project. Runner no longer ships a second chat host or `quickHostMode` chat implementation.
- Open Chat transfers the current prompt and any completed or partial inline answer to the actual Standalone application. The transcript is initialized as context only; it is not auto-submitted again.
- If Standalone is already running, a bounded current-user-only named-pipe handoff opens a new real Full Agent conversation window inside the existing Standalone process, preserving the current chat window and its conversation. If no Standalone process exists, Runner locates the executable and starts it with a short-lived bounded handoff file.
- Standalone remembers its executable path in current-user Local AppData. Runner checks running processes, registered install paths, this path cache, conventional locations and development output paths.
- If a second Standalone process starts during an existing instance's startup, it retries the current-user pipe briefly; if the existing listener remains unavailable, it falls back to opening the handoff in its own genuine Standalone window rather than dropping the user's context.

## Windows build correction — stale retired Runner chat XAML

A user-run build from a reused extraction directory picked up an obsolete `RunMind.Runner/RunnerChatWindow.xaml` left behind by an earlier source package. The file is absent from the current source archive, but extracting a newer ZIP over an older folder does not remove retired files. The Runner project now excludes both `RunnerChatWindow.xaml` and `RunnerChatWindow.xaml.cs` through `DefaultItemExcludesInProjectFolder`, with explicit WPF `Page` and C# `Compile` removals as defense in depth. `Build-Release-x64.bat` also deletes these two retired files before restore/build when they remain in a reused source directory. This keeps the retired WebView2 chat host out of builds even when upgrading source in place. Regression tests protect both the project exclusions and build-script cleanup.
