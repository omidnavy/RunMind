# RunMind 3.4.0 — Release notes

RunMind 3.4.0 brings the Full Agent workspace and the optional Runner quick launcher into one source release line. The source contains four Windows host projects:

- **Standalone:** full RunMind desktop workspace.
- **PowerToys Run:** full Agent plugin.
- **Command Palette:** full Agent extension packaged as a signed MSIX.
- **Runner:** optional restricted Quick Host with unified search and inline model support.

## Major capabilities

- **Project Intelligence:** project understanding/diagnostics, Mission Control and Git-aware Change Impact Explorer v2.
- **Deep Research:** editable plans, source/evidence collection, claim assessments and report export.
- **Agent workflows:** bounded orchestration, checkpoints, review-before-resume, MCP Streamable HTTP and Skills.
- **Developer Infrastructure:** Node debugging/profiling, Playwright browser workflows, API/backend testing, development-server management, SQLite and Podman/Docker integrations.
- **System Manager:** Windows application/process/service/event/crash/network/storage/security/task and adapter operations with separate native permissions.
- **Live Resource Intelligence:** explicit bounded CPU, memory, GPU, network and process-I/O sampling, in-memory charts and CSV export.
- **Process Intelligence:** selectable live process inventory, on-demand detail inspection, file/signature/owner/security/parent/child metadata, executable reveal, copy actions, graceful close, force termination and guarded restart.
- **Runner:** unified app/file/URL/calculator/model results, global or keyword activation, configurable plugin weights, dynamic window sizing and Standalone handoff.

## Version metadata note

The source bundle/release line is referred to as 3.4.0, but project metadata is not yet uniform: Standalone, PowerToys Run and Command Palette projects remain at 3.3.1 (the Command Palette MSIX identity is 3.3.1.0), while Runner is 3.4.0. This mismatch is retained rather than silently changing package identities during a documentation cleanup; unify and validate the host/package versions before publishing a uniformly versioned release.

## Important boundaries

- Runner is not a Full Agent and does not expose workspace, file attachments, developer, MCP, Skills or System Manager tools.
- MCP uses Streamable HTTP; STDIO transport is not included.
- Live Resource sampling is user-started and bounded. It continues while its flyout is hidden but ends on Stop, expiry or RunMind window teardown. Samples are retained in memory, not written as a persistent telemetry store.
- GPU readings depend on Windows driver-exposed performance counters. Per-process GPU attribution and live process working-directory inspection are unavailable.
- Process restart is restricted to eligible same-account/current-session processes. It uses RunMind's current token and an executable-folder working-directory fallback; it cannot recreate the original token, current directory, inherited handles or app state. Service-hosted and protected Windows processes are blocked from process-level actions.
- Native actions use the current Windows account; RunMind is not a sandbox and does not silently elevate.
- Full Chat and shared PowerToys Run/Command Palette credentials are not all DPAPI-protected. See [Security and privacy](docs/SECURITY-AND-PRIVACY.md).

## Build and validation

Run `Build-Release-x64.bat` on Windows with the .NET 10 SDK. It builds all four host projects, publishes Standalone and Runner, and packages/signs Command Palette; it does not install them. Use the host-specific installers separately.

Portable tests and static source checks do not certify the current C# build, WebView2 behavior, MSIX activation, PDH GPU counters or process actions. See [Build status](BUILD-STATUS.md) and the current Windows acceptance guides.
